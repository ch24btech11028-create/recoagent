Notes, in order of how much they should temper the numbers:

1. n is 7 and 11. These are directional, not statistically meaningful.
2. The gate rejected nothing in either run. The model declined instead of
   guessing on every case it could not explain, which is the behaviour you
   want but means the live runs did not exercise the rejection path. That
   path is covered by test_a_confident_wrong_proposal_is_rejected, where 7
   proposals at 0.97 confidence were all refused.
3. "Resolved" means the arithmetic closed and the credit was matched to the
   correct settlement. It does NOT verify the model's stated *reason* is the
   true cause. A proposal can close the sum for the wrong reason; the pairing
   still comes from the UTR join, so this cannot create a false match, but it
   can create a misleading audit note. Measuring explanation accuracy against
   the injected class is not yet implemented.
4. Held-out scored higher than dev (63.6% vs 57.1%), which is the opposite of
   overfitting -- but see point 1.
5. Tool calling is broken on this endpoint: asked to call a function the model
   returns tool_calls=None and writes malformed pseudo-JSON into content.
   The proposer uses plain JSON mode and validates with the same strict parser
   as the Anthropic path.
