# RecoAgent

Two-leg settlement reconciliation. Deterministic solvers do the matching, an
LLM explains only what they could not match, and every explanation must survive
an arithmetic replay before it becomes a match.

> **Solvers find matches. The LLM proposes why the rest didn't match — and no
> hypothesis is accepted until the arithmetic closes.**

---

## Results — rung B0 (deterministic baseline)

2,000 orders → 2,036 payments → 164 settlement batches → 164 bank credits.
Held-out run uses a different seed **and** a defect mix the matcher was never
tuned on. Full artifacts in [`results/`](results/), regenerated by the commands
below.

| | dev | **held-out** | clean (control) |
|---|---:|---:|---:|
| **False-match rate** | **0.00%** | **0.00%** | **0.00%** |
| Auto-match rate | 93.85% | 93.85% | 100.00% |
| Credit value matched | 75.40% | 73.77% | 100.00% |
| Leg 1 recall (order → payment) | 95.40% | 95.40% | 100.00% |
| Leg 2 recall (credit → batch) | 75.00% | 75.00% | 100.00% |
| Exceptions with no injected cause | 0 | 0 | 0 |
| Ground-truth accounting | reconciles | reconciles | reconciles |

Runtime: **0.14s** for the full 2,000-order batch, single-threaded, no
dependencies.

**Read the first row first.** A reconciliation engine that matches everything
and is occasionally wrong is worse than useless: it books money against the
wrong transaction and hides the error behind a green number. BenchRec, the
ICAIF 2023 industry benchmark for this exact task, puts it plainly — it is
better to leave a transaction unmatched, and leave it for manual review, than
to match it incorrectly. So false-match rate leads, throughput follows, and the
exception list is published rather than summarised.

**Why dev and held-out agree at the aggregate level.** By construction: the two
mixes hold each leg's *total* defect rate constant and invert the composition
(`PARTIAL_CAPTURE` 56→32, `DUPLICATE_PAYMENT` 36→60, `REFUND_NETTED` 7→3,
`FEE_TAX_VARIANCE` 4→7). Identical totals make the comparison fair; the per-class
tables in `results/b0_*.txt` are where the distributions actually differ, and
they are where a tier tuned to dev proportions will show a drop.

## Run it

Python 3.11+. The deterministic core has **no third-party dependencies**.

```bash
python -m recoagent.run --n 2000 --seed 7
```

```bash
python -m recoagent.run --n 2000 --seed 21 --profile holdout --exceptions 5
```

```bash
python -m pytest -q
```

## Verify it

Five checks, each falsifiable. The run exits non-zero if the first and last fail.

1. **False-match rate is 0.00%.** Exact keys plus an arithmetic gate cannot
   produce a wrong pairing. Anything above zero is a bug.
2. **Auto-match rate is below 100% on a defective book.** If B0 resolved
   everything, the injected defects would be decorative.
3. **The clean profile matches 100% with zero exceptions.** The control. Proves
   the matcher is not rejecting undamaged records.
4. **Injected defect counts equal accounted counts, per class.** Printed as the
   exception-accounting table. A divergence means some class lands where the
   matcher never looks, and every rate above it is flattering itself.
5. **Zero exceptions with no injected cause.** Complaints about clean records
   are matcher bugs.

Determinism:

```bash
python -m recoagent.run --n 2000 --seed 7 --out /tmp/a.json && python -m recoagent.run --n 2000 --seed 7 --out /tmp/b.json && diff /tmp/a.json /tmp/b.json && echo identical
```

**The matcher cannot see the answer key.** `tests/test_independence.py` parses
the AST of every matching module and fails if any of them imports the
generator or references a ground-truth type. A matcher that can reach the
labels can be tuned against them, accidentally or otherwise.

The suite is mutation-checked: breaking the proof gate, clipping narrations at
a fixed column instead of inside the UTR, or letting a matcher import the
generator each produce failures. Worth noting that the first of those does
*not* trip the false-match-rate check — the UTR join still picks the right
batch, it just accepts one whose money is wrong. That is precisely why the
accounting check exists alongside the headline number.

## Layout

```
recoagent/
  money.py         integer paise, MDR/GST with per-step rounding
  defects.py       the twelve-class exception taxonomy
  schemas.py       entities + the SourceBundle / LabelledBatch split
  generator.py     synthetic three-source world, labelled defect injection
  validate.py      the arithmetic gate — the LLM tier's only privilege
  legs/leg1.py     order ↔ payment, 1:1
  legs/leg2.py     bank credit ↔ settlement batch, N:1
  pipeline.py      rung assembly
  eval/scorer.py   false-match rate, accounting, value coverage
  run.py           CLI
results/           committed run artifacts
tests/             41 tests
```

See [ARCHITECTURE.md](ARCHITECTURE.md) for the design decisions and what is
deliberately not built yet.

## Data and attribution

All figures above come from synthetic data generated by this repository. No
merchant data, real or sampled, is used anywhere. Evaluation against
[BenchRec](https://www.kaggle.com/datasets/benchmarkteam/benchrec-real-world-cash-reconciliation-dataset)
(ICAIF 2023) is planned and **not yet done** — every number here is
self-generated, which is exactly why the independence and accounting checks
above are the load-bearing part of the evaluation.
